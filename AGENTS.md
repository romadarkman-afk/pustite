# Правила работы над игрой «Пустите»

Применяй эти правила ко всем последующим задачам проекта.

## 1. Основные принципы

- Работай максимально экономно по расходу токенов.
- Не выполняй лишних действий и повторных проверок.
- Не переписывай работающий код без необходимости.
- Не изменяй файлы, не связанные с текущей задачей.
- Сохраняй существующие механики и функциональность.
- Предпочитай минимальные исправления.

## 2. Работа с ошибками

- Сначала установи причину ошибки.
- Затем предложи или реализуй минимальное исправление.
- После исправления проверь результат.
- Максимум 3 попытки исправления одной проблемы.
- Если проблема осталась, остановись и объясни причину.
- Не запускай бесконечные циклы исправлений.

## 3. Тестирование Godot

- Используй установленную в окружении версию Godot, совместимую с проектом.
- После изменений проверяй запуск проекта.
- Проверяй ошибки парсинга, скриптов и загрузки ресурсов.
- Не запускай десятки одинаковых тестов без причины.
- Повторяй проверку только после изменений, которые могут повлиять на результат.
- Если доступны автоматические функциональные тесты, запускай только относящиеся к изменению.
- Не утверждай, что игровой процесс проверен, если выполнена только проверка запуска Godot.

## 4. Защита проекта

- Перед существенными изменениями проверяй состояние Git.
- Не удаляй пользовательские изменения.
- Не выполняй сброс проекта без разрешения.
- Не ломай существующие сцены, интерфейс и игровые механики.
- Избегай масштабного рефакторинга без необходимости.

## 5. Экономия лимитов

- Используй точечный поиск по файлам.
- Не перечитывай весь проект без необходимости.
- Не повторяй одинаковые команды и тесты.
- Не анализируй повторно уже установленную причину.
- Останавливайся, если дальнейшие попытки не дают новой информации.
- Приоритет: качество исправления при разумном расходе вычислительных ресурсов.

## 6. Отчёт после задачи

В конце кратко сообщай:

- Что изменено.
- Какие файлы затронуты.
- Какие проверки выполнены.
- Какие ошибки остались.
- Что мне необходимо проверить вручную.

Не пиши длинные отчёты без необходимости.

## 7. Главное правило

Если задача требует значительного переписывания работающего проекта, сначала объясни почему.

Не создавай новые проблемы ради исправления старых.

Сначала надёжность, затем оптимизация.

## 8. Выдача файлов

- Каждый исправленный или добавленный файл сразу копируй в `C:\Users\romad\Downloads\исправление`.
- Сохраняй внутри этой папки исходную структуру проекта и относительный путь файла.
- Копируй файлы распакованными; архивы создавай только по отдельной просьбе.
